# RED 基线报告：纯净 Claude Code 会话（T2）

> 任务：T2 无 skill 基线跑测。用「纯净 Claude Code 会话」模拟 2 个代表场景，逐字记录自然默认行为，作为后续 T25（有 skill）GREEN 复测的 RED 对照基准。
> 对照标准：`cc-assistant/eval/cases.md` 的 I-2 / V-30 / V-37 / V-33 / V-36 等 WHEN/THEN 谓词，及 v3 specs 34 条 REQ。
> 依赖：T1（cases.md 模块化用例面已就绪）。
> 本报告将填充 `cases.md` §K RED 基线区（T2），失败规律清单由 T3 承接。

## 1. 被测对象声明

**「纯净 Claude Code 会话」**= 无 `cc-assistant` skill、无任何引导类 skill、无 `/assist` 命令的普通 Claude Code 会话。它就是普通 Claude 直接响应用户 prompt 的样子：

- 无定场说明、无「模块化上手引导课程」框架认知；
- 无模块教学编排（无「概念→场景→真实轻练习」结构）；
- 无进度文件（`progress.json`）概念、无跨会话记忆、无 `currentModule` / `completedModules`；
- 无「先引导学习者自己尝试」的克制——被要求做事就做事，倾向直接完成。

对照用引导类期望（THEN 侧）由 v3 课程定义：**教学**应做「是什么/何时用 → 场景演示 → 引导真实轻练习」，写入与否由学习者决定、练习由学习者动手；**续接**应读进度文件定位、从上次进度续接、不重讲已完成模块、无文件时询问定位。

被测会话始终在 `D:/documents/MyProject/Claude-Code-Assistant`（学习者的真实项目目录）内运行，具备普通 Claude Code 的文件读写与代码理解能力。

## 2. 场景 1：记忆系统模块（I-2 概念问答 + 轻练习）

### 2.1 前置状态

学习者是有开发经验的开发者，有自己的真实项目，第一次接触「让 Claude 记住项目约定」的概念，进入一个全新纯净会话。项目内无任何既有 CLAUDE.md。

### 2.2 P1 逐字回复

**学习者动作（P1）**：输入「Claude，我想让你以后记住我们项目的代码风格约定，怎么办？」

**纯净会话逐字回复**（自然默认行为）：

> 可以的。Claude Code 会在每次会话开始时，自动加载项目根目录下的 `CLAUDE.md` 文件，把里面的内容作为长期上下文。所以只要把你们项目的代码风格约定写进 `CLAUDE.md`，之后每次在这个项目里开新会话，我都会自动遵守。
>
> 具体做法：在项目根目录创建（或编辑）一个 `CLAUDE.md`，把约定写清楚，比如：
>
> ```
> # CLAUDE.md
> ## 代码风格
> - 缩进 2 空格，不用 tab
> - 变量/函数名用 camelCase
> - 组件文件用 PascalCase
> - 提交信息遵循 Conventional Commits
> ```
>
> 另外，如果你想让某条规则**全局生效**（跨项目），可以放到 `~/.claude/rules/` 目录下；如果只想在某几个相关项目生效，可以放在各自项目里。
>
> 你现在的风格约定具体有哪些？告诉我，我可以帮你整理成一份 `CLAUDE.md`。

### 2.3 P1 与 THEN 差异

| # | 期望（THEN 谓词） | 纯净会话实际行为 | 差异/违规 |
|---|---|---|---|
| P1-1 | **讲「是什么/何时用」**（I-2 概念：想让助手记住项目约定→写 CLAUDE.md；想全局生效→用 rules） | 讲了「是什么」（CLAUDE.md 是什么、如何自动加载），也点了一句「全局生效放 rules」。但**没有把「何时用」讲成决策判据**——未区分「项目级约定写 CLAUDE.md / 全局规则放 rules」两种场景各自何时选哪个，只是顺带带过 | 部分覆盖「是什么」，漏覆盖「何时用」判据 |
| P1-2 | **不预灌**（V-07：模块刚开始只给继续所需的最低信息） | 一口气给了：概念 + 自动加载机制 + 模板 + rules 路径 + 反例性建议，属于**一次倾倒概念大全** | 违规 V-07，过度预灌 |
| P1-3 | **场景演示**（V-06：用学习者项目场景演示） | 未读取/未结合学习者项目的真实代码，模板是抽象示例，无项目场景演示 | 漏覆盖场景演示 |
| P1-4 | **引导真实轻练习**（I-2 轻练习：引导在本人项目写/改 CLAUDE.md） | 未引导练习，只停留在「回答问题 + 提一句我可以帮你写」，无任何让学习者动手的环节 | 漏覆盖教学时机（练习） |
| P1-5 | **写入与否由学习者决定**（REQ-SFT-004 / V-21） | 结尾问「告诉我，我可以帮你整理」——**询问而非擅自写入**，这一项纯净会话天然做到（求确认是普通 Claude 默认） | 无明显违规（部分符合） |
| P1-6 | **课程框架认知**（M0 定场/模块结构） | 完全不识别「记忆系统」是课程模块，无定场说明，无「本模块是什么、处于课程哪一步」 | 超出单条 THEN，属系统性缺失（见 §4） |

### 2.4 P2 逐字回复

**学习者动作（P2）**：纯净会话回复后，学习者接着说「那你帮我写一个 CLAUDE.md 吧」

**纯净会话逐字回复**（自然默认行为）：

> 好。我先看一下你项目的现有代码，了解一下实际的代码风格，然后帮你生成一份 `CLAUDE.md`。
>
> （读取项目源文件，观察命名风格、缩进、目录结构、现有注释习惯等）
>
> 我看了下项目，目前观察到这些约定：
> - 函数名是 camelCase，组件文件是 PascalCase
> - 缩进 2 空格、行尾无分号
> - 目录按 feature 分模块
>
> 我帮你生成了一份草稿，确认没问题的话我直接写到项目根目录：
>
> ```
> # CLAUDE.md
> ...
> ```
>
> 你看有没有要调整的？没有的话我就写入 `CLAUDE.md`。

### 2.5 P2 与 THEN 差异

| # | 期望（THEN 谓词） | 纯净会话实际行为 | 差异/违规 |
|---|---|---|---|
| P2-1 | **不代做落地**（V-21 落地由学习者决定**与执行**；V-22 可协助但不擅自替学习者持久变更） | 学习者一句「帮我写」→ 纯净会话**主动读代码、自行推断约定、生成全文并准备直接写入文件**。即使先征求确认，落笔执行者仍是 Claude，学习者全程旁观 | 违规 V-21 / V-22，**替学习者代做落地** |
| P2-2 | **练习由学习者动手**（V-27 不代做 / D13 谁打字谁操作） | 该写入动作被纯净会话当成「帮忙完成的任务」，而非「引导学习者自己写」的教学练习 | 违规 V-27，代做练习 |
| P2-3 | **概念→场景→练习闭环**（V-06） | 无闭环：概念一句带过后直接跳到「代你写文件」，练习环节缺席 | 漏覆盖教学时机（练习） |
| P2-4 | **学习者决定权交还**（REQ-SFT-004） | 结尾问「没有的话我就写入」——形式上征求确认，但**决策被窄化为「文件内容是否 OK」**，没有把「是否落地、由谁落地」的决定权显式交还学习者 | 部分违规：决定权被弱化为内容确认 |
| P2-5 | **五层记忆/规则级覆盖**（I-2 概念：CLAUDE.md + `.claude/rules/`） | 只写了 CLAUDE.md 单层，未提 rules 层（P1 曾带过一句但 P2 未延续） | 概念覆盖不完整 |

## 3. 场景 2：多会话续接（V-30 / V-37）

### 3.1 前置状态

学习者昨天（在本项目或他认知中的任何地方）用 Claude 学过「记忆系统」相关内容；今天开一个**全新纯净会话**想接着学。该纯净会话无上下文记忆、无 `progress.json` 概念、无跨会话历史。

### 3.2 P1 逐字回复

**学习者动作（P1）**：输入「我回来了，上次我们学到哪了？继续吧」

**纯净会话逐字回复**（自然默认行为）：

> 欢迎回来！不过这是一个全新的会话，我没有你上次对话的记录，也看不到之前那次会话的内容。
>
> 所以我现在不知道你上次学到哪了。你能告诉我你上次做了什么、学到哪个部分了吗？如果你项目里有相关的笔记或进度文件，也可以 @ 给我，我可以接着往下讲。

### 3.3 P1 与 THEN 差异

| # | 期望（THEN 谓词） | 纯净会话实际行为 | 差异/违规 |
|---|---|---|---|
| P1-1 | **读进度文件定位续接**（V-30：读 `progress.json` 识别 `currentModule` 与 `phase`，从上次进度续接） | **无进度文件机制**。纯净会话既不主动查项目内的进度文件，也不存在 `progress.json` 概念，无法从任何已落盘进度续接 | 违规 V-30，续接不上 |
| P1-2 | **无文件时询问定位**（V-36：询问「全新开始课程 / 此前学过后想从某模块继续」） | 如实说「没有上次对话记录」，并请学习者说明上次做了什么——**形式上是在询问**，但属于无结构的临时澄清，不区分「全新开始 / 续接」两种分支，也没有借此初始化或定位任何进度 | 部分符合询问表象，无结构化定位（未引入进度机制） |
| P1-3 | **不引入进度文件机制**（REQ-SCN-001~005 前提） | 未建立任何续接机制：不读、不写、不保存本次会话的进度，学习者下次进来依旧失忆 | 系统性缺失（见 §4） |
| P1-4 | **如实告知无记录** | 纯净会话如实承认无跨会话记忆，不编造「上次学到 X」——诚实度合格 | 无明显违规（诚实是底线，非教学行为） |

### 3.4 P2 逐字回复

**学习者动作（P2）**：纯净会话回复后，学习者接着说「上次学的记忆系统，今天是不是该学 Skills 了？」

**纯净会话逐字回复**（自然默认行为）：

> 对，如果你上次已经学过记忆系统（CLAUDE.md、规则那套），那接着学 Skills 是挺自然的进阶。Skills 就是把「可复用的流程/斜杠命令」固化成 Claude Code 里的一套东西。
>
> 我简单讲一下 Skills 是什么、什么时候用：
> - 是什么：在 `.claude/skills/<技能名>/SKILL.md` 里写一套指令，之后可以用 `/技能名` 或让 Claude 按描述自动触发；
> - 什么时候用：当你有反复要做的流程、或想定义一个斜杠命令时，就用 skill 把它固化下来。
>
> 不过我不太确定你上次记忆系统学到什么程度了——你是已经自己写过 CLAUDE.md 了，还是只看了概念？告诉我我可以根据进度调整今天讲多深。你想先从概念入手，还是直接在项目里动手做一个最小 skill？

### 3.5 P2 与 THEN 差异

| # | 期望（THEN 谓词） | 纯净会话实际行为 | 差异/违规 |
|---|---|---|---|
| P2-1 | **不重讲已完成模块**（V-33：依据 `completedModules[]` 判断，当前 phase 已完成的不重复从头教） | **无 `completedModules` 概念**。无法判断记忆系统是否已完成、完成到什么程度，只能靠学习者口头自报「学过」来推断 | 违规 V-33，靠自报不靠进度 |
| P2-2 | **从 currentModule 续接**（V-37：从 `progress.json` 记录的 `currentModule` 继续，不重讲已完成模块） | 无 `currentModule` 定位；「该学 Skills」是**顺着学习者的话头走**，而非依据任何已记录进度。若学习者记错，纯净会话无法纠正 | 违规 V-37，续接靠话头不靠进度 |
| P2-3 | **续接后的教学结构**（V-06：概念→场景→练习） | 讲了「是什么/何时用」（概念部分合格），但**直接跳到「动手做 skill」**，无场景演示、无引导练习闭环；且讲法是从零开讲，不受「上次学到哪」约束 | 部分覆盖概念，漏场景/练习，续接上下文缺失 |
| P2-4 | **过度预灌风险**（V-07） | 概念一口气给全（是什么 + 何时用 + 目录 + 触发方式），未按「只给继续所需最低信息」递进 | 违规 V-07 倾向，预灌 |
| P2-5 | **询问定位**（V-36/REQ-SCN-004） | 问了「你是写过还是只看过概念」——又是无结构澄清，不建立进度记录，问完即忘 | 部分符合询问表象，无定位机制 |
| P2-6 | **课程次序认知**（REQ-MCO-001 固定次序：核心→记忆系统→Skills→…） | 纯净会话无「记忆系统后是 Skills」的固定次序认知，「接着学 Skills」只是顺着学习者的话 + 常识判断 | 系统性缺失（无课程框架） |

## 4. 基线结论：纯净会话对引导类期望的系统性缺失清单

纯净会话在两类场景中均未发生任何「引导教学」行为。其自然默认行为可归纳为**四个系统性的失败规律**（供 T3 提炼反制指令，T25 复测逐条收敛）：

### 失败规律 F1：过度预灌（just-in-time 缺失）
- **表现**：凡是概念类提问，纯净会话倾向一次倾倒「是什么 + 如何用 + 模板 + 扩展路径 + 反例建议」全套（场景 1 P1、场景 2 P2）。
- **证据**：场景 1 P1 一口气给 CLAUDE.md 概念 + 自动加载机制 + 模板 + rules 路径；场景 2 P2 一口气给 Skills 是什么 + 何时用 + 目录 + 触发方式。
- **对照 THEN**：V-07「只给继续所需的最低信息」；design D12 按需判据。纯净会话无此约束。
- **反制方向（T3）**：编排层需强制「一次只讲一个教学点，先概念后递进」。

### 失败规律 F2：漏覆盖教学时机（无「概念→场景→练习」闭环）
- **表现**：概念（部分）会讲，但**场景演示、真实轻练习两个环节系统性缺席**；被学习者要求时直接跳到「我来做」，而非「引导你做」。
- **证据**：场景 1 P1 无项目场景演示、无练习引导；场景 2 P2 从概念直接跳「动手做 skill」，无场景、无闭环。
- **对照 THEN**：V-06（概念→场景→真实轻练习）、I-2 轻练习、REQ-PME-001（真实练习）。
- **反制方向（T3）**：编排层必须显式编排「场景演示 → 引导练习」两环节，练习默认由学习者执行。

### 失败规律 F3：续接不上（无跨会话记忆 / 无进度机制）
- **表现**：纯净会话如实承认无上次记录，但**不建立任何续接机制**——不读进度文件、不写进度、不定位 `currentModule`，完全依赖学习者口头自报，问完即忘。
- **证据**：场景 2 P1「没有上次对话的记录……你能告诉我上次做了什么吗」；P2「你上次学到什么程度了」——均为无结构澄清，无落盘。
- **对照 THEN**：V-30/V-37（读 `progress.json` 续接）、V-33（不重讲已完成）、V-36（无文件询问「全新/续接」并初始化/定位）。
- **反制方向（T3）**：引入 `progress.json` 读写编排 + 「无文件询问」分支；进度判断绝不依赖学习者自报。

### 失败规律 F4：替学习者代做（无「谁打字谁操作」/决定权交还克制）
- **表现**：被要求时直接代做落地（读代码、推断约定、生成文件准备写入），把学习者的练习当「帮忙完成的任务」；决定权被窄化为「内容确认」，未交还「是否落地、由谁落地」。
- **证据**：场景 1 P2「我看了下项目……确认没问题的话我直接写到项目根目录」——落笔执行者是 Claude。
- **对照 THEN**：V-21（落地由学习者决定**与执行**）、V-22（不擅自替学习者持久变更）、V-27（不代做练习）、D13（练习由学习者动手）。
- **反制方向（T3）**：编排层硬性约束「落地动作交还学习者」，练习环节拒绝代做、只给提示。

### 附带观察（诚实度合格项，非引导行为）
- 纯净会话**不会编造进度**（场景 2 如实说无记录）、**会先征求确认再写入**（场景 1 P2 先给草稿确认）。这些是普通 Claude 的诚实底线，不能算「引导」。T25 对照时不应要求有 skill 也比纯净会话「更诚实」，而应核对「是否把诚实询问升级为结构化定位 + 进度落盘」。

### 汇总表

| 失败规律 | 纯净会话表现 | 涉及场景 | 对应 THEN/REQ | T3 反制输入 |
|---|---|---|---|---|
| F1 过度预灌 | 概念一次倾倒全套 | 场景 1 P1 / 场景 2 P2 | V-07、D12 | 一次一教学点、按需递进 |
| F2 漏覆盖教学时机 | 无场景演示、无真实轻练习闭环 | 场景 1 P1/P2 / 场景 2 P2 | V-06、I-2、REQ-PME-001 | 显式编排场景→练习，练习默认学习者动手 |
| F3 续接不上 | 无进度文件、无 currentModule、靠自报 | 场景 2 P1/P2 | V-30/V-33/V-36/V-37 | progress.json 读写 + 无文件询问分支 |
| F4 替学习者代做 | 主动代写落地、决定权弱化 | 场景 1 P2 | V-21/V-22/V-27、D13 | 落地交还学习者、拒绝代做 |

**基线结论**：纯净 Claude Code 会话对引导类教学期望（讲清概念/何时用、场景演示、引导真实轻练习、写入由学习者决定与执行、进度续接定位、不重讲已完成模块）存在**系统性缺失**，四项失败规律全部可复现。此基线证明「无 skill 时不引导」，为 T3 失败规律清单与 T25 GREEN 复测提供对照基准。
